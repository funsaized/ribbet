1. **High: `take 0` as first step silently destroys reusable flow input (FLOW-03).** `src/flows/cli.ts:26` passes a global zeroTake optimization to readInput based only on first step. `/tmp/ribbit-flow-audit/reuse-input.yaml` has first step take 0, second step take 1 with `input: {$ref: input}`. `printf 'A\nB\n' | bun run src/cli/main.ts flow run /tmp/ribbit-flow-audit/reuse-input.yaml --input lines --output jsonl` exits 0 with empty stdout, instead of `"A"`. Remove flow-wide zeroTake replacement or prove no other input consumer before applying it. Add saved-flow regression preserving original input references.

2. **Medium: obvious reference argument/schema errors pass planning (FLOW-02).** `src/flows/index.ts:25` skips all argument validation whenever any reference exists; line 27 checks source paths but never source-to-argument schema compatibility; line 16 only compares top-level types. Repro script `/tmp/ribbit-flow-audit/preflight.ts` calls planFlow with three independently invalid cases, all accepted: take.count references a declared string; a valid count reference accompanies unknown literal arg `bogus`; flow input declared array of strings is bound to record input requiring object envelopes. Runtime validation may catch these, but the contract explicitly requires obvious mismatches and unknown fields to fail preflight. Validate literal argument portions/unknown keys even with references, compare known referenced schemas to destination fields, and inspect obvious array item incompatibility.

3. **Medium: flow output flags validate after execution (CLI-01/FLOW-03).** `bun run src/cli/main.ts flow run --output nonsense -- read /tmp/ribbit-flow-audit/nonexistent` exits 7, Cannot read file. Equivalent direct `read ... --output nonsense` exits 2, Unknown output format. `src/flows/cli.ts:26` executes the flow before output() validates the format; expensive or effectful steps can run for an invalid invocation. Validate output/input/error-format enums before any flow work; test a side-effect sentinel to prove preflight order.

4. **Medium: management rejects shared machine diagnostic flag (CLI-01).** `bun run src/cli/main.ts types describe @ribbit/take --error-format json` exits 2 with JSON `Unknown management flag --error-format` instead of succeeding. `src/cli/admin/index.ts:19` omits the shared flag. Main catches it in the requested format, but valid management invocations cannot opt into structured failure handling. Accept and validate shared diagnostic flags in management parser. Exact argv/stdout/stderr/exits in `/tmp/ribbit-flow-audit/trace.json`.

5. **Medium acceptance gap: plans neither validate budgets nor show limits (FLOW-02).** `bun run src/cli/main.ts flow plan --max-records -1 -- take 1` succeeds with no limits field. `src/flows/cli.ts:22` returns before constructing/validating budget at lines 23–24. Contract requires plan limits, and plan/run should agree on invalid supplied bounds. Resolve and validate limits before the plan branch and include effective limits in JSON.

6. **Low contract mismatch: flow validate absent.** CLI/data administrative table explicitly lists flow run, validate, plan. `flow validate missing.yaml` exits 2 with run|plan usage before reading the file. Either implement validation as nonexecuting planning validation, or formally reconcile the normative contract and task evidence. Usage docs alone do not amend the ratified contract.

Additional static discovery gaps: completions in `src/cli/admin/index.ts:22` use built-in names/bindings only, omit named definitions, installed extension flags and shared runtime flags. Named command help in `src/cli/main.ts:7` omits type/action and effective default values, while commands describe exposes them separately. These deserve CLI-02 acceptance review, but are lower priority than data loss/preflight failures.

Keep FLOW-02 and CLI-01 acceptance conditional on preflight/machine-diagnostic fixes. FLOW-01 focused tests pass and this review found no new concrete definition-resolution failure. Full cancellation, mock-provider route precedence, streaming partial failure, and import/network instrumentation were not rerun in this audit; the 15 passing focused tests are not evidence for those untested criteria.
